DFlash2 比普通投机解码快的真正原因：块扩散草稿模型（4⭐，No.130）

一句话要点

DFlash2 的速度来自块扩散草稿模型的结构：掩码扩散模型一次前向同时提出整块 K 个候选 token，验证仍由目标模型把关、输出与目标模型完全一致；再用约 200 万参数的成对选择器与两抽头动态卷积补上并行起草丢掉的局部依赖，代价只有约 1% 延迟。

为什么值得读

  • 多数解读把 DFlash2 说成“投机解码，只不过草稿模型并行”，抓错了重点。这篇把并行性追溯到草稿模型的结构本身：掩码扩散按构造就能同时预测多个位置，自回归按构造就只能顺序生成，两者的差别不是工程优化的程度，而是分解方式。
  • 它把投机解码、扩散模型、屋顶线模型三条线串在同一个论证里：无损保证只约束验证步骤，不约束草稿怎么产生提议；块扩散把起草推向张量核心友好的胖矩阵乘法；每块只从 HBM 读一次草稿权重。读完能同时理解机制、硬件与数字。
  • 基准数字的版本归属讲得很干净：“15 倍”是 DFlash v1 在 gpt-oss-120b 上的特定吞吐/交互结果，不是 DFlash2 的通用说法；加速比随批量与上下文长度衰减、高并发下甚至可能输给 MTP，这些细则都摆在明面上。

核心结论

  • 投机解码的无损性只约束验证步骤：接受/拒绝规则正确计入提议分布 q，输出 token 的分布恰好就是目标模型 p；温度为零时退化成 argmax 一致才接受。草稿模型怎么产生提议不受约束，这正是自回归草稿模型可以换成扩散草稿模型的自由。
  • 每轮期望 token 数 E = (1 − α^(K+1)) / (1 − α)，随接受率 α 凸性增长、随 K 饱和。更好的草稿模型回报不成比例地高，更长的草稿只有近乎免费时才有帮助，两点都直指扩散草稿模型。
  • 自回归草稿模型的瓶颈是结构性的：T_draft = K · t_step，K 次顺序前向；τ 随 K 饱和、T_draft 随 K 线性增长，超过小的最优 K*，多起草反而有害。EAGLE-3 在 DFlash 的 Qwen3-8B 配对实验里约 2.1～2.3 倍（其论文别处峰值最高 6.5 倍，应看作常见实际区间，不是架构上限）。
  • 块扩散是插值：跨块自回归（全局连贯、长左上下文），块内扩散（下一块的 K 个位置并行）。一步去噪产生各位置边缘分布的乘积，是真实块联合分布的均值场式近似，块级散度非负，只在联合分布恰好可分解时取等。
  • DFlash2 的两处补强都便宜：成对选择器约 200 万参数、约 0.6% 延迟；两抽头动态卷积约 3% 参数、0.7% 延迟。对比 DSpark 式修正约 7780 万参数、约 9.6% 延迟，新增参数约少 40 倍、延迟开销约低 16 倍，接受率恢复得更多。
  • 硬件上，块并行起草把工作推向计算密集区，Blackwell 的 FP4/FP8 张量核心受益最大；约 20 亿参数 FP8 草稿模型（约 2GB），K=8 时自回归每块约 16GB 权重流量对约 2GB，理想模型省约 14GB、8TB/s 下约 1.75ms（上界，非实测）。

投机解码一节讲清，附无损保证

  • 批量为 1 的自回归解码严重浪费 GPU 张量计算：工作负载受显存带宽限制，大权重矩阵流过 HBM，只产出一个 token 的工作量，张量核心大部分时间都在等显存。
  • 经典投机解码（Leviathan 等，2023；Chen 等，2023）把小草稿模型 q 与大目标模型 p 配对：起草（q 提出 K 个候选 token）、验证（p 一次前向给全部 K 个打分）、接受或拒绝（按规则逐个接受或拒绝，能证明复现 p）。
  • 对草稿 token x ~ q(x)，抽 r ~ U(0,1)，若 r < min(1, p(x)/q(x)) 则接受；第一次拒绝时，从残差分布 p_res(x) = (p(x) − q(x))₊ / Z 重采样并停止。输出 token 的分布恰好就是 p：Pr[X = x] = min(q(x), p(x)) + (p(x) − q(x))₊ = p(x)。

人人继承的瓶颈：草稿模型是自回归的

  • 一轮的 wall-clock 代价是 L = (T_draft + T_verify) / τ，验证与 K 无关，都是一次前向。结构性问题在起草内部的串行依赖链：token i 不存在就产不出 token i，K 次顺序前向。
  • EAGLE-3 是出色的工程，特征级起草、多层融合、树验证一应俱全，但草稿头仍然是自回归的，深度 K 仍然意味着 K 个串行步骤。
  • 要去掉这条链，必须把并行性移进草稿模型自己的结构。扩散是最自然的成熟模型家族之一，掩码 token 模型按构造就能同时预测多个位置，不过它不是唯一的并行起草思路（Medusa、MTP 与 Jacobi 式解码也放松了严格的从左到右起草）。

重点：扩散语言模型为什么是合适的草稿模型

  • 自回归模型用链式法则：p(x₁..ₖ | c) = ∏(k=1..K) p(xₖ | x_＜k, c)，精确，但把顺序生成硬编码进了分解式。掩码（吸收态）离散扩散模型的谱系是 D3PM、SEDD、MDLM，块级别是 BD3-LM（Block Diffusion）。
  • 前向过程以速率 αₜ 把每个 token 独立替换成 [MASK] 状态；学到的逆过程从掩码 token 预测干净 token，给定掩码输入，最终的 token 预测在位置上分解：p_θ(x₀ | xₜ, c) = ∏ᵢ p_θ(x₀ⁱ | xₜ, c)。给定 xₜ，各位置的 token 分布条件独立，这正是一次前向能预测整块的原因。
  • DFlash 不是简单采用标准块扩散训练，而是一套任务专用的配方：选锚点/上下文 token，把剩下的投机块掩码以匹配推理模式，再用位置加权交叉熵 wₖ = exp(−(k−1)/γ) 训练，给靠前的位置更高权重，因为位置 k 出错会让它之后的一切失效。
  • DFlash 把目标模型的隐藏状态投影进每个草稿层的 Key/Value 表示，实现跨块条件；非因果块对角注意力让 K 个掩码位置双向互看，也看注入的上下文。这是 BD3-LM 的想法，专用化成草稿模型。
  • 后缀衰减有实测数据：Recall@16 从第一个投机位置的 99.5% 降到第 6 个位置的 87.8%，Recall@1 从 85.4% 降到 72.9%。分析归因于主干容量有限（5 层草稿模型）、块内注意力随深度下降（第 1 层约 30%，到第 5 层约 8%）、局部 token 间交互太少。边缘乘积的视角给出了预期会出现一致性缺口的理由，它本身并不能预测单调衰减。
  • 一次生成整块的两点结构优势：其一，没有离散的块内误差传播，采样错误不会污染之后所有的草稿状态；其二，训练与推理的差距小得多，训练时掩码一块并以锚点为条件，高度贴合推理时的样子，大幅缩小了教师强制与自由运行之间的不匹配。

透过扩散视角看 DFlash2，与 DSpark 对比

  • 两抽头动态卷积 Conv(x)ₜ = k(t,0) ⊙ xₜ + k(t,1) ⊙ xₜ₋₁，恢复了独立输出分解所缺的显式近邻隐藏状态耦合，不是离散自回归条件。实测上，它释放了注意力预算，深层平均块内注意力从约 9.4% 降到约 0.5%，后缀衰减缓解。
  • CRF 式成对选择器：每位置保留 top-16 候选，再给相邻候选加一个低秩兼容度。φₜ(a,b) = ⟨ A(a) ⊙ H(hₜ), B(b) ⟩，Sₜ(a,b) = Uₜ(b) + φₜ(a,b)，路径能量 score(x₁..ₖ) = Σₖ [ Uₖ(xₖ) + φₖ(xₖ₋₁, xₖ) ]。DFlash2 不跑维特比算法，也不全局优化这条路径能量；成对分数并行算出，然后从上一个已验证 token 出发，做一次便宜的贪心游走，每步跟最优后继。
  • 为什么这是正确的杠杆：第一个投机位置上，正确 token 约 99.5% 的时间已在 top-16 里，但贪心 top-1 选择每轮只接受约 4.27 个 token，top-16 上的神谕选择能到约 6.79。候选通常是对的，任务是挑一条连贯的路径。
  • DSpark 本身的设计目标也是在并行起草里恢复 token 间依赖结构，结论不是它不好用，而是在这个基座上，一个轻得多的成对打分选择器拿到了大部分收益。

扩散草稿模型同样是硬件论证：GPU、显存与 CPU

  • 计算的形状：批量为 1 的自回归起草步是瘦长的类矩阵向量运算，算术强度约 1～4 FLOP/byte，张量核心大多空闲。块扩散起草把全部 K 个位置一起处理，把大部分工作变成更胖的矩阵乘法。屋顶线模型上，B200 的拐点（约 4500 FP8 TFLOP/s 除以 8TB/s）约 560 FLOP/byte；把 K 个位置打包成批，工作负载滑向计算屋顶，也就是 Blackwell 的 FP4/FP8 张量核心所在的位置。
  • KV 缓存：先纠正一个常见误解，DFlash 确实维护草稿 KV 缓存，投影后的目标特征注入草稿模型的 K/V 并存在那里，跨迭代复用。优势不是“没有草稿缓存”，而是 DFlash 不用一个独立的自回归草稿模型重新编码整个上下文。容量仍然重要：KV 字节数 = 2 × L × H_kv × d_head × S × b，27B 级目标模型、8K 上下文下每条序列约 1GB；上下文变长会侵蚀加速比（设备实测，2K 上下文约 2.1 倍，8K 上下文降到约 1.34 倍）。
  • 主机一侧：一次 Transformer 前向是多个 kernel，所以不是“K 次 kernel 启动对一次”，有意义的区别是 K 次顺序草稿前向调用对一次块并行前向调用。现代引擎用设备端采样、异步调度与 CUDA 图藏起大部分，但块内依赖链仍然限制并发。
  • 精度：块内没有采样 token 的反馈，某个位置的量化误差不会级联到后面的位置，这让块并行起草成为激进量化的理想目标。这是合理性，不是保证：近期的 INT4 DFlash 结果依赖量化感知蒸馏与对量化目标的适配。
  • 哪些 GPU：H100 SXM（80GB，约 3.35TB/s，无 FP4）；H200 SXM（141GB，约 4.8TB/s，无 FP4），Hopper 计算相同，HBM 更多更快；B200 SXM（约 180GB HBM3e，最高约 8TB/s，原生 NVFP4），甜点位置；GB200 NVL72，机架级 Blackwell。B200 的 HBM 带宽最高约 H200 的 1.7 倍（约 2.4 倍的跃升是 B200 对 H100）。

基准测试：版本归属与细则

  • DFlash v1（单流/系统峰值）：gpt-oss-120b 在 Blackwell 上高达 15 倍（固定交互目标，8 台 DGX B300）；Gemma 4 31B 5.8 倍（Math500，vLLM，1 台 Blackwell，并发 C=1）；Qwen3-8B 5.1 倍（Math500，SGLang，1 台 B200，并发 C=1）；单流加速比 EAGLE-3 高约 2.5 倍。
  • DFlash2（已发布模型，批量为 1）：Qwen3.8-27B-DFlash2 2.7～3.4 倍；Muse-Glimmer-30B-DFlash2 3.1～4.6 倍；Qwen3.5-4B 上平均接受长度 5.97，高于 v1 的 4.92，提升 21%。
  • 需要说明的提醒：加速比随批量增大而衰减（gpt-oss-120b 并发 C=1 时约 1.8 倍，到 C=64 时约 1.5 倍）；高并发下甚至可能输掉（一次独立的 H100 实测里，Gemma 4 31B 密集版在并发 C=16 时 DFlash 约 725 token/s，MTP 约 953 token/s）；目前只有 Qwen3.8-27B 与 Muse-Glimmer-30B 提供 v2 草稿模型；“无损”是相对于实际运行的目标模型而言的（设备上通常是 4 比特量化版）。

结论要点

  • DFlash 的关键想法不只是“用扩散代替自回归”，而是把自回归依赖链从起草阶段本身去掉。掩码块草稿模型在一次并行模型调用里提出几个未来 token，投机验证保留目标模型的输出。
  • DFlash2 接着聚焦并行性仍会丢质量的两处：从候选 token 里挑一条连贯路径（CRF 式成对选择器加贪心游走，约 200 万参数），以及恢复短程块内一致性（两抽头动态卷积），并证明两者都能便宜地改进，不必放弃并行起草。
  • 更深的教训是：当并行性是草稿模型的结构属性，而不是叠加在另一个自回归循环之上的优化时，投机解码会变得有趣得多。DFlash 是迄今最清晰的示范之一。

局限

  • 均值场视角只是解释，不是定理：它给出预期会出现一致性缺口的理由，但不能预测单调衰减；后缀衰减的具体机制来自 DFlash2 的实验归因（主干容量、块内注意力随深度下降、局部交互太少）。
  • 15 倍、5.8 倍等峰值数字都绑定特定模型、任务、引擎与硬件配置，通用化引用会失真；加速比随批量与上下文长度衰减，高并发下 DFlash 甚至可能输给 MTP。
  • 目前只有 Qwen3.8-27B 与 Muse-Glimmer-30B 提供 v2 草稿模型，覆盖面窄；“无损”是相对于实际运行的量化目标模型而言的。
  • 1.75ms 的 HBM 节省是屋顶线式的上界，不是实测的延迟节省；INT4 结果依赖量化感知蒸馏与对量化目标的适配，不是块并行结构自动给出的保证。

可复用的点

  • 选草稿模型先看结构能不能并行，再看工程优化：并行性是结构属性，不是叠加在自回归循环之上的优化。
  • 均值场近似丢掉的依赖，不必用重结构补回来：轻量成对打分加贪心游走，在这个基座上拿到了 DSpark 式重修正的大部分收益，参数约少 40 倍、延迟开销约低 16 倍。
  • 位置加权训练：给靠前的位置更高权重，因为位置 k 出错会让它之后的一切失效；训练配方要匹配推理模式（锚点加掩码块），缩小教师强制与自由运行的不匹配。
  • 硬件选型：块并行起草把工作推向计算密集区，Blackwell 的 FP4/FP8 张量核心受益最大；做推理服务时，KV 容量与上下文长度是加速比的实际约束，先算 KV 字节数再定批量。
