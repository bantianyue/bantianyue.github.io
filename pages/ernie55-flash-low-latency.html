ERNIE 5.5 Flash：逼近解码极限

ERNIE 5.5 Flash：逼近解码极限，在 SGLang 上跑到 1074 tokens/s（中文精读）

  • 原文：Toward the Decode Limit: ERNIE 5.5 Flash at 1074 tokens/s on SGLang（https://www.lmsys.org/blog/2026-11-23-ernie55-flash-low-latency）
  • 收藏：2026-11-25
  • 主题：推理优化、并行策略（推理）、Kernel 优化
  • 星级：⭐⭐⭐⭐（重点阅读）
  • 一句话要点：ERNIE 5.5 Flash 在 SGLang 上把解码做到 1074 tokens/s：三刀切关键路径——HCA 压缩器与晚块注意力走旁路流、mHC 两次串行归约双线性展开合并成一趟、路由/专家计算/跨卡归约融进 MegaLLMoE 单核；DSpark 一次前向并行出整块候选，每步 token 数翻倍。

为什么值得读

小 batch 解码是推理里最难啃的形态：每步只有一个 token 在跑，算术强度低到按 roofline 模型算就是访存受限，瓶颈全在关键路径的串行开销上。ERNIE 5.5 Flash 还是大稀疏 MoE 模型，用 mHC 在层间维持多条残差流，每个细粒度架构细节都会加访存、同步与通信开销。这篇把优化沿三条线拆开——权重读取、固定开销、通信延迟——每条线都有可复用的具体打法，机制、架构图、6 卡实测与复现命令都全。

核心结论

  • 瓶颈定性：解码速度等于每步产出 token 数除以每步延迟。优化分两个方向：减少步数（投机解码一次前向验证多个候选）；压低每步延迟（权重读取推向带宽极限、算子融合消除固定开销、与计算重叠藏起通信延迟）。
  • 并行方式从 DP/EP 切到 TP：注意力用数据并行时，全部访存与计算落在部分 rank 上，其余 rank 空等；张量并行把计算与权重读取均匀分到所有 rank，只付少量通信。MoE 同理：EP 要在专家计算前后各做一轮跨卡交换，TP 只需对专家输出做归约，还把每个专家均匀切到所有 GPU 上，消掉路由不均的负载倾斜。
  • 细粒度 GEMM：Blackwell 的 FP8 UMMA 指令为大矩阵设计，batch 1 加 TP 切分后矩阵维数很小，粗 tile 填不满 SM。模拟 m16n8k32 MMA 指令把 tile 切得更细；token 少于 8 个时用 swapAB，把 token 维映射到 N 维减少 padding。小 GEMM 比 DeepGEMM 的 FP8 GEMM 最多快 1.9 倍（2048×1024 GEMM、6 个 token：4.30 微秒降到 2.23 微秒）。路由专家再用 W4A8 混合精度（FP4 权重配 FP8 激活），比 FP8 少一半权重访存流量。
  • 算子融合与多流：合并相邻小算子（Norm、RoPE、merge），每解码步去掉数千次核启动与内存读写；对称内存让跨卡通信变成相邻计算核尾部的几条远程写指令，数据本身当到达信号。互不依赖的计算发到不同流上并行跑，限制非关键路径核的 SM 数；几乎所有核都用 PDL 启动，相邻核的启动与收尾开销重叠。

三刀切关键路径

  • HCA 压缩器走旁路流：超过 80% 的层用 HCA 注意力。压缩器只有攒满一整块压缩 token 才产出新的压缩 KV，但执行链排在注意力核前面，拖慢核的启动，自身 GPU 利用率又很低。把压缩器连同依赖新压缩 KV 的那一块 KV 的注意力（晚块注意力）拆出来，放到旁路流上用空闲 SM 跑，轻量 release/acquire 信号通知主 stream 的 combine 核收结果。还给 TP 下每 rank 16 个头设计了折叠尾块的注意力核：KV 缓存块独立调度，query 的 RMSNorm 与 RoPE 融进注意力 prologue，合并后的注意力输出直接广播到每个 rank。
  • post-mix 与逆 RoPE 换序：VHA post-mix 先对注意力输出做逆 RoPE 再跨头线性混合，逆 RoPE 结果必须先写回 HBM 再被 post-mix 读进来。逆 RoPE 在每个头内做同样的旋转，post-mix 作用在正交维度上，按结合律可以换顺序；再把逆 RoPE 与输出投影的量化合并进 post-mix 阶段，省掉两趟 HBM 往返。原来被通信隔开的四个后处理步骤缩成两个核。
  • One-Pass mHC：mHC 的聚合权重与归一化尺度都依赖全局归约，两次串行归约构成依赖链。内积的双线性把聚合结果的平方范数展开成聚合权重在残差流 Gram 矩阵上的二次型；Gram 矩阵只依赖输入，在算聚合权重的同一趟归约里一起算出来，归一化尺度随后由廉价标量算术得出。两次串行归约合并成一趟。层间跨卡通信、mHC 与低精度量化再融进一个核；Sinkhorn 迭代与 MoE 没有数据依赖，排到单独的流上并行跑。
  • MegaLLMoE 单核：Multi-Router Latent MoE 层里两组路由器给每个 token 从 512 个专家里选 10 个，路由专家在 2048 维潜空间算，共享专家处理 4096 维隐藏输入。MegaLLMoE 把路由、专家计算与跨卡归约融进一个 CUDA 核，每 rank 一次 launch 完成整层前向：路由器、Latent Down 与共享专家由不同 CTA 并行算，Latent Down/Up 与专家计算支持 Split-K；Gate 与 Up 权重交错存放，TMA 整块加载；8 个 CTA 一组协作算同一个专家；潜空间与隐藏空间各只做一次 AllReduce，单轮 NVLS 多播，第一次归约按输出就绪一块传一块，与剩下块的计算重叠。
  • DSpark 投机解码：一次前向并行生成整块候选，起草成本不随推测长度线性增长；目标模型一次前向验证多个 token。每步时间增加不到一半，每步产出的 token 数翻倍。

实测数字

4 卡 SM100 GPU、CUDA 13.0、PyTorch 2.14.1、HALOps 0.2.0；batch 1、55K 输入 token、1K 输出 token；注意力 TP4、MoE TP4；DSpark 模拟接受长度 5.5。解码速度由平均 TPOT（每输出 token 时间，不含第一个 token）算出，为 1 / TPOT；每步时间是 TPOT 乘以接受长度。

优化阶段 每步时间 (ms) 解码速度 (tokens/s)
朴素 DP/EP 实现 9.80 102
低延迟后端 / TP 7.52 133
DSpark 投机解码 10.5 524
通信计算融合 / 多流 / PDL 7.27 757
One-Pass mHC / 量化融合 6.58 836
注意力数据流重构 / 多流管理 5.80 948
MegaLLMoE 5.12 1074

DSpark 块大小 7、模拟接受长度 7.2 时，每步时间升到 5.50 ms，但每步产出更多 token，解码约 1310 tokens/s。

值得注意的点

  • 口径：FP4 检查点在 Hugging Face 与 ModelScope 上，自带 DSpark 草稿；复现命令里环境变量 SGLANG_SIMULATE_ACC_LEN=5.5 是模拟接受长度，不是实测接受率。
  • 与 vLLM-GR（No.115）同属一条推理优化主线：把关键路径上的工作移出串行段、让一次 launch 或一次会话做更多事；与 11 月 19 日的 SGLang Megakernel、11 月 24 日的 Miles 真 On-Policy 也是同一条线。
  • 这部分工作有 AI RSI 的参与，ERNIE Evolve 贡献了很多优化思路；核心核（低延迟 GEMM、MegaLLMoE 融合算子、One-Pass mHC）已在 HALOps 仓库开源。
