Triton/Gluon 布局：数据分给哪个线程、存在哪，全由布局定

  • 原文：https://jino-rohit.github.io/blogs/21_gluon_layouts.html
  • 收藏：2026-11-24
  • 主题：Kernel 优化
  • 一句话要点：布局就是一张所有权表：给定 wave、lane 和 lane 内的值序号，就能算出它持有张量的哪个元素；共享内存里 swizzle 与 padding 靠重排与留白换 bank 对齐。

为什么值得读

写 Triton kernel 绕不开布局，但多数教程只给结论不给算式。这篇从 512 个值分给 256 个线程的最小例子起步，把 Blocked 布局的四个字段、线性布局的位基、共享内存的 swizzle 与 padding 全都落实到可以手算的数字上：lane 5 的二进制、bank = (byte_address // 4) % 32、q + 16 × (q // 512)。同一个 64×64 拷贝 kernel，换一种布局，汇编里取数前的地址算式就变了，合并访问变非合并访问——布局不是装饰，是性能。

核心结论

  • 布局描述数据如何分布在线程间：给定 wave、wave 里的 lane、lane 内的值序号，就能算出它持有张量的哪个元素。张量的 stride 则决定元素在内存里的地址，两者是不同问题。
  • BlockedLayout 四个字段：size_per_thread（每线程拿多少元素）、threads_per_warp（每 wave 多少线程）、warps_per_cta（每 block 多少 wave）、order（主序）。1 × 64 × 4 = 256 个值，正好等于向量形状。
  • 张量比模式大时分配重复：1,024 个位置分给同样的 256 个线程，模式每 256 个元素重复一次，0 号线程拿 x[0]、x[256]、x[512]、x[768]。
  • order=[1, 0] 是行优先：8×8 的 lane 网格里 lane 0 右边是 lane 1，走完 8 个 lane patch 换下一行。
  • 同一个 64×64 FP32 拷贝 kernel，合并布局里 lane 乘 4，字节偏移 0、4、8、12 落在一个块里，GPU 能合起来；非合并布局多一次左移 6 位（乘 64），偏移 0、256、512、768 在四个不同的块里，需要分别访问。
  • 线性布局把归属写成位基的异或：每个输入位单独为 1 时的贡献就是基，ID 里有多个 1 位时选中对应的基异或组合。512 个值的分配：reg_bases=[[1]]、lane_bases=[[2],[4],[8],[16],[32],[64]]、warp_bases=[[128],[256]]。
  • MI300X 的 LDS 有 32 个 bank，每个 4 字节宽，bank = (byte_address // 4) % 32。0 号线程读字 0、1 号线程读字 64 时，两个请求都进 bank 0，争同一个 bank，要分开服务，这就是二路 bank 冲突。
  • Swizzle 把同一批张量值换个顺序存在共享内存里，改变它们用的 bank，元素的逻辑值不变。规则是 new_group_position = group_number XOR phase，组打乱但 8 个一组的向量组保持完整。A[2,3] 从位置 3 换到位置 11。
  • Padding 每 512 个元素位置之后插入 16 个填充元素，物理元素偏移是 q + 16 × (q // 512)。代价是多占 LDS 容量，通常要权衡。
  • 填充布局的 14 个基对应槽号 q 的 14 位，2¹⁴ = 16,384 种组合，每个数据槽一个；六个列基组合得到 0–63 的每一列，八个行基组合得到 0–255 的每一行。

逐节要点

  • 什么是布局：512 个值的向量、256 个线程，布局就是回答"谁拿哪个值"的表；stride 回答"元素在内存里的地址"。
  • Blocked 布局：四个字段的含义；size_per_thread=[2] 时每线程两个相邻值；张量比模式大时分配每 256 个重复一次。
  • 把思路扩展到矩阵：形状 [16, 32] 的布局写法；order=[1, 0] 行优先；拷贝 kernel 在两种布局下的汇编对照，合并与非合并的差别只在取数前算 v0 的指令。
  • 线性布局：slot/lane/wave 三个 ID 的位数；lane 5 的位表；从 Blocked 布局推导基；等价的 DistributedLinearLayout 写法。
  • 共享内存布局：bank 映射公式；二路 bank 冲突的例子；SwizzledSharedLayout 的 vec/per_phase/max_phase；A[2,3] 的位置追踪。
  • 填充布局：[[512, 16]] 的含义；槽号 q 的定义；14 个偏移基与 16,384 个坐标。

局限

  • 只覆盖 Triton kernel 里最常见的布局，线性布局"还能做什么"留待后续展开；例子全部基于 MI300X 的 LDS（32 个 bank、4 字节宽），换硬件要重新算 bank 数。
  • 没有给吞吐或带宽的实测数字，合并与非合并的差别只讲到"合起来"与"分别访问"，没有量化。

可复用的点

  • 算布局的通用办法：先把 ID 落实（几位、取值范围），再逐个试"只有一个输入位是 1"的输入，读出基，最后异或组合。
  • 判断 bank 冲突的速算：bank = (byte_address // 4) % 32，同一访问阶段里两个线程进同一个 bank 就是冲突。
  • 填充偏移公式 q + 16 × (q // 512)：每 512 个元素插 16 个空隙，偏移 511 不变，512 变 528，1,024 变 1,056。
