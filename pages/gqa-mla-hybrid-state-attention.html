从 GQA 到 MLA 再到混合状态：注意力压缩如何改写推理系统

  • 原文：Inference Infrastructure (4): Attention: From GQA and MLA to Hybrid State（Medium，Johney Zheng，推理基建系列第 4 篇，2026-11-24 收藏）
  • 原文首发：Johney Zheng 的博客
  • 主题：推理优化、KV 缓存、注意力架构、并行策略（推理）
  • 星级：⭐⭐⭐⭐（重点阅读）
  • 一句话要点：注意力压缩分两条线：Qwen 线用 GDN 线性化绕过 KV，DeepSeek 线沿通道、读取、序列三个正交维度逐维压缩；选哪条线，决定 KV 容量、每步读取字节与可切分性——压缩倍数本身不是答案，三把标尺合起来才是。

核心结论

  • 看注意力变体对推理系统的影响，要看三样东西：KV 容量、每步读取字节数、算子能不能切分。按这三把标尺，MLA、GDN 与压缩注意力改写推理系统的方式各不相同，代价也各不相同。
  • 两条演进线：Qwen 线从 MHA 到 GQA 再到 3:1 的 GDN 与 GQA 混合，用线性化绕过 KV；DeepSeek 线从 MLA 的通道维压缩，到 DSA 的稀疏读取，再到 CSA/HCA 的序列维压缩，沿三个正交维度逐维压缩，始终保留 softmax。
  • MLA 把每 token KV 从 1.9 MB 压到 70 KB（28 倍），但潜变量全头共享，张量并行只能复制不能切分，解码注意力变成算力受限。
  • GDN 用固定大小状态替代 KV，45 层只占 94 MB，但前缀缓存部分失效，容量规划必须分两段算。
  • CSA/HCA 沿序列维继续压缩：压缩路径与滑窗路径在查询处汇合，索引器选 top-1024，提速 2 倍、召回 99.7%。

两条演进线

Qwen 线：MHA → GQA（全部 Qwen2）→ 3:1 GDN+GQA 混合（Qwen3-Next 验证，Qwen3.5 放大）。思路是直接替换 75% 的注意力层，用线性化绕过 KV。

DeepSeek 线：MHA → MLA（V2，通道维压缩）→ +DSA（V3.2，稀疏读取）→ CSA/HCA（V4，序列维压缩）。思路是保留 softmax，在内部沿通道、读取、序列三个正交维度逐维压缩。

KV 尺寸是推导估计值，不是框架最终分配的量：Qwen 全注意力部分约 30 KiB/token，Kimi 的 61×576×2 约 68.6 KiB/token；GLM 的 78×576×2 约 87.8 KiB/token，只覆盖潜变量加 RoPE，索引器等状态要另算。DS-V4 约 10KB/token 的数字是基于压缩布局的早期量级估计，不能当固定常量用。混合精度、页对齐与额外缓存字段都会改变实际占用。

MLA：压缩通道维

做法：K 与 V 共享一个低秩中间表示，不按头存储。x 经 W_DKV 得到 512 维潜变量 c_KV，再经 W_UK、W_UV 得到 K_nope 与 V；RoPE 部分单独存 64 维，位置相关，不能被吸收。

每 token KV = L × (512 + 64) × bpp = 61 × 576 × 2 = 70 KB，对 MHA 的 61 × 16384 × 2 = 1.9 MB，小 28 倍。

矩阵吸收（解码必需）：不吸收时，每步先把潜变量解压回完整 K 再算注意力，省了显存，却每步多付一次巨大的解压 matmul。吸收是提前把 W_UK 并进 W_UQ，让查询直接在潜变量空间里做点积：q_nope · k_nope^T = x·(W_UQ·W_UK^T)·c_KV^T。本质是摊销：预处理 token 少的那一侧。解码时只有一个查询，吸收稳赚；预填充时两侧一样长，吸收反而要付从 128 维到 512 维的每对开销，预填充用不吸收的 MHA 形态。不吸收的代价：128K 上下文下，每步浪费约 4400 GFLOPs，是模型全部活跃参数算力（约 74 GFLOPs）的 60 倍。

系统后果：潜变量由全部头共享，没有头维度可切分，张量并行下只能复制不能切分，注意力必须用数据并行；token 随之散到各卡，MoE 层需要一次 all-to-all 再把它们聚回来。P/D 传输里，没有头维度反而意味着无需重排。

瓶颈在转移：吸收后 128 个头共享 576 维潜变量，解码时算术强度 I 约 242（BF16），高于该配置 37 到 42 的脊点，解码注意力主要受算力限制。实测 FlashInfer MLA 达到 85 到 106 TFLOPS，只用 0.4 TB/s 带宽；B=32、s=32K 时单层 3.2 毫秒，时间与头数乘上下文成正比。这个结论只适用于此处实测的每卡 128 头配置；KV 压缩仍带来容量收益，但延迟并不随字节减少同比例下降。该配置下验证（q_len=2）的注意力时间升到 2.0 到 2.2 倍。TP8 切到每卡 16 头时，I 约 30，WGMMA 的 M 维填不满，只达到 23 到 26 TFLOPS，算力与带宽都没饱和，128 头的瓶颈结论不再适用。

GDN：不压缩，直接绕过去

做法：GDN（Gated DeltaNet）用固定大小状态的递推更新，替代 softmax(QK^T)V 的二次复杂度。基础线性注意力 S_t = S_{t-1} + k_t v_t^T，输出 o_t = q_t^T S_t；GDN 加两处改动：S_t = α_t·S_{t-1} + β_t·k_t(v_t − k_t^T S_{t-1})^T。

两个机制各管一摊：门控 α控制忘掉多少历史，状态不会无界累积；Delta 规则只写预测错的那部分。没有它，同一个 key 反复出现会让状态范数爆炸（实测重复 12 次：基础线性注意力的状态范数达到 18.5，GDN 保持在 3.2）。

GDN 层没有随序列增长的标准 KV，但持有固定大小的状态（Qwen3.5 每请求约 94 MB，是布局估计值，实际数字取决于状态精度、卷积状态与检查点策略）。

系统后果之一，内存曲线分两段：Qwen3.5 的 45 层 GDN 持有固定大小状态，只有 15 层全注意力层有 KV：Mem(req) = 94 MB + s × 30 KB。按上述布局估计，交叉点约 3K token；短请求里固定大小状态可能比 KV 还大。容量规划公式必须有两段，单个 s×KV 项会严重低估短请求。

系统后果之二，前缀缓存部分失效：标准 KV 是只追加的，前缀的 K/V 保持完整、可复用；GDN 状态是有损压缩的整个前缀摘要，没法截断回第 n 个 token。折中是保留多个检查点，但这些检查点也是窗口化的，不是连续的。

CSA/HCA：沿序列维继续压缩

CSA 与 HCA 共享同一套注意力层数据流：压缩路径把隐状态投影成内容与权重 logit，分组 softmax 后聚合成压缩条目；滑窗路径保留最近 128 个 token 的未压缩 KV。CSA 在压缩条目上加稀疏选择，HCA 直接拼全部条目；两路在查询处汇合，拼成该注意力步的 KV 集合，再走共享 KV 的 MQA 与输出侧 RoPE。

底层只有中间段不同：CSA 层 m=4，重叠流，索引器选 top-1024，保留局部细节；HCA 层 m'=128，单流，对全部条目做稠密计算，提供粗粒度全局上下文。Pro 版共 61 层，先 2 层 HCA 再交替，两路都带窗口与注意力 sink。KV 布局：压缩条目进 KV Cache（块 = lcm(4,128) = 128 个原始 token），窗口 KV 与未压缩尾部进 State Cache，各自独立淘汰。

索引器（Lightning Indexer，FP4）用共享低秩查询向量打分，top-k 选 1024 个压缩条目，提速 2 倍、召回 99.7%。滑窗存在的原因是因果查询只能看到更早的完整压缩块，窗口补回查询所在块内的近期细节。

值得注意的点

  • KV 压缩的收益不在延迟上：MLA 的例子里，KV 少 28 倍，解码注意力却变成算力受限，延迟不随字节减少同比例下降。容量收益与延迟收益要分开算。
  • 潜变量共享是一把双刃剑：省了 KV，但拿掉了头维度，张量并行只能复制；MoE 层为此多一次 all-to-all，P/D 传输反而省了重排。
  • GDN 的 94 MB 是固定成本：短请求（3K token 以下）里固定状态比 KV 还大，容量规划不分两段会低估短请求。
  • 前缀缓存对混合状态部分失效是结构性代价：GDN 状态是有损摘要，截断与复用要靠多检查点折中，不是免费修复。
  • 文中 KV 尺寸、状态大小多处标明是布局估计值或早期量级估计，引用时别当固定常量用。
