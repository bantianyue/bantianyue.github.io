一句话要点

llm-d 现在可以选 SGLang 做推理引擎后端，与 vLLM 共用同一套 Kubernetes 编排、前缀感知路由与分层 KV 缓存：每个注意力 DP rank 成为独立可路由的 InferencePool 端点，P/D 配对状态复制到全部 rank；L1 显存、L2 内存、L3 共享存储三层 KV 缓存下，16 卡单副本并发 128 的输出快 3.94 倍，32 卡双副本加共享 L3 后故障转移以 99.94% 命中率恢复 1.08M token。

为什么值得读

  • 它讲清楚了“第二个引擎不能意味着第二个平台”怎么做：llm-d 把编排、路由、P/D 分离抽到平台层，引擎只暴露每 rank 端点与 P/D 分离契约。换引擎只换部署 overlay 与路由配置，网关、自动扩缩、缓存路由栈不用重建。
  • Wide-EP 接入的卡点很具体：一个节点级端口藏了 8 个 KV 缓存、P/D 配对只在 rank 0 上工作、路由器看不到每 rank 的缓存命中。解法也具体：每 rank 内嵌 Rust HTTP 服务器、配对状态全 rank 复制、EPP 里解码 SGLang KV 事件。
  • 分层 KV 缓存的数字分得清场景：L2 内存消除单副本的 L1 抖动悬崖（命中率 85%–95%）；共享 L3 在单副本上反而拖慢稳态（TTFT +14%–33%），只在故障转移与冷重启时值回票价（恢复 99.94% 前缀 token、冷恢复 TTFT -57%）。结论是按场景选层，不是全开。
  • 部署配方可直接跑：两步（helm 装路由器 + kubectl 应用 overlay），16 卡与 32 卡两种布局、共享 L3 的 PVC 前置条件都给了。

核心结论

  • 引擎无关平台：DisaggregatedSet 做声明式 prefill/decode 分离编排（gang 调度、滚动更新、GPU 与 RDMA 网卡动态资源分配）；每 DP rank 注册为独立 InferencePool 端点；EPP 路由管线按 rank 跟踪已缓存前缀与在途 token，选热前缀 prefill rank 与最轻负载 decode rank。
  • SGLang Wide-EP 接入三改：每 DP rank 内嵌 Rust HTTP 服务器（带每 rank 预热就绪检查）；P/D 配对状态复制到全部 rank 监听器，OpenAI 与原生 API 间携带路由元数据，标准 Linux DMA-BUF RDMA 做 KV 传输，prefill 失败时干净取消 decode；按 rank 暴露模型与启动元数据，跨节点关联 P/D trace 与日志，EPP 解码 SGLang KV 事件。
  • 三层 KV 缓存：L1 每卡 261K token、每 8 卡 prefill pod 2.09M token（约 20–30 个仓库级会话）；L2 每 rank 98.4 GiB 固定内存，单 pod 扩到 L1+L2 共 17.5M token；L3 在 9,000 GiB 共享卷上存约 163M token，GLM-5.2 的 MLA KV 表示跨 rank 相同，页面文件无 rank 后缀、去重共享。
  • 单副本实测（16 卡 1P1D，AIPerf inferencex-agentx-mvp，Claude Code trace，142K 上下文，并发 16–128）：并发超 32 后 L1 命中率跌到 6.0%，并发 128 的 TTFT 中位数 174.2 秒；L2 把命中率稳在 85%–95%，TTFT 中位数降低 8.7 倍，输出提升 3.94 倍（319→1,257 tok/s）。共享 L3 单副本上 TTFT +14%–33%、输出 -9%，无明显额外收益。
  • 多副本实测（32 卡，2 prefill 副本 + 2 节点 decode 池）：并发 128 的 TTFT 中位数降低 5.9 倍到 3.43 秒，输出 1,903 tok/s；无故障时共享 L3 让 TTFT +26%（并发 64）/+66%（并发 128），输出 -5%–11%。故障转移（t=95 秒删 prefill-0，24 个约 98K token 会话）恢复 99.94% 前缀 token，TTFT 中位数 -25%（38.4→28.8 秒）；冷副本恢复 TTFT -57%（38.8→16.8 秒）。
  • 运维结论：稳定单副本 pod 跑 L1+L2，Spot 抢占、升级或多副本故障转移的韧性重要时再加共享 L3。
  • 下一步：把 sglang-processor（SGLang 的 P/D 分离 Rust 预处理层）与 llm-d 路由器接起来，prompt 在入口只渲染与分词一次；再配每 rank Rust 指标与跨 L1/L2/L3 的 KV 事件流，路由从近似前缀跟踪走向精确的块级缓存感知。

分节要点

  • 引言：上一篇用 vLLM 在 H200 上服务长上下文编码智能体；此后 SGLang 成为 llm-d 参考部署里一流的 Kubernetes 原生推理引擎；三部分：引擎无关架构、SGLang 集成、分层 KV 缓存卸载。
  • llm-d 架构与引擎无关设计：统一 Kubernetes 控制与路由层；声明式 P/D 分离编排、每 DP rank 的 InferencePool 端点发现、可插拔 EPP 路由管线；SGLang 暴露同样契约即可接入。
  • 一流的 SGLang 集成：Wide-EP 边界不匹配（专家共享、每 rank 独立 KV 缓存）；三处改动（每 rank Rust 端点、P/D 配对状态复制、每 rank 可观测性）。
  • 分层 KV 缓存卸载与多副本性能：L1/L2/L3 三层定义与容量；单节点内存扩展实测；多副本共享 L3 实测（故障转移与冷恢复）。
  • 部署配方：两步部署（helm 路由器 + kubectl overlay），16 卡与 32 卡布局，共享 L3 的 PVC 前置条件。
  • 结论：支持第二个引擎不建第二个平台；HiCache 让长会话随流量增长而存活；按场景选 L1+L2 或加共享 L3。
  • 下一步：sglang-processor 接入路由器，prompt 入口只渲染分词一次；块级缓存感知路由。
