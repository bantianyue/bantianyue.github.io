NVFP4 注意力寄存器回收：N128 拆成两个 N64，核延迟最高 1.64 倍

中文精读 ｜ 原文：https://developer.nvidia.com/blog/how-to-optimize-nvfp4-attention-on-nvidia-rtx-blackwell-through-register-recycling/

NVFP4 注意力寄存器回收：N128 拆成两个 N64，核延迟最高 1.64 倍（4⭐，No.150）

一句话要点：SageAttention3 在 RTX Blackwell SM120 上用 NVFP4 跑 QK 与 PV；N128 分数 tile 拆成两个 N64 寄存器槽，一半指数化并量化后回收它的分数寄存器，算下一个 tile 对应一半的 QK；核延迟最高 1.64 倍，端到端延迟最多降 15.34%。

为什么值得读：数据中心 Blackwell 上注意力以 softmax 为界，RTX Blackwell 上则以 MMA 为界，同一套 FlashAttention 管线搬不过来；这篇把“寄存器不够”这个硬约束变成调度设计：95.3% 的寄存器已占满，装不下第二块分数 tile，于是把 N128 拆成两半、死掉的分数寄存器立刻复用；核延迟与端到端延迟都有实测，且核心优化已合入 FlashInfer 主分支。

核心结论： - 服务世界基础模型时，注意力是主要瓶颈；Hopper 与 Blackwell 数据中心 GPU 上 FlashAttention3/4 靠块内重叠 MMA 与 softmax 提速，但这条硬件专属管线搬不到 RTX PRO 6000 Blackwell（SM120）上——Tensor Core 架构不同，BF16 推理的世界模型里注意力仍以 MMA 为界。 - NVFP4 提供硬件加速的 4 位矩阵乘法，Tensor Core 吞吐更高；但要维持高吞吐，得仔细协调 softmax、数据搬运与中间存储，阶段间的依赖会让 Tensor Core 空闲。 - SageAttention3 是专为 SM120 设计的原生 NVFP4 注意力机制，QK 与 PV 都用 NVFP4 跑；主要创新是对 P 做两级缩放：NVFP4 量化生成 NVFP4 数据张量与 FP8 缩放张量，softmax 输出被限制在 [0, 1] 窄范围、会用不满 NVFP4 动态范围，两级缩放先归一化、再量化。 - CTA 用 4 个生产者 warp 与 8 个消费者 warp；每个 N128 tile，消费者依次执行 QK、softmax 与概率量化、PV，串行执行导致张量核活动出现空隙。 - 约束：TMA 加载被绑定在 128×128 的形状上；Blackwell RTX 的 OMMA 操作被限制在 m16、n8、k64；k=128 要发两条 k=64 的 MMA 指令，且 MMA 执行是同步的，消费者 warp 要等完成才能继续。 - 寄存器约束：生产者 warp 用 3,072 个寄存器，消费者 warp 用 59,392 个，合计 62,464 个，占 SM 寄存器容量的约 95.3%，装不下第二块完整的分数 tile。 - 优化：每个 N128 分数 tile 拆成两个 N64 半块，各占一个独立的寄存器槽；一半指数化并量化后，回收它的分数寄存器、算下一个 tile 对应一半的 QK；下一个 tile 的 QK 与当前 tile 剩余的 softmax、量化与 PV 交错；在线 softmax 状态仍跨整个 N128 更新。 - 实测（RTX PRO 6000 Blackwell Server Edition，96GB，SM120）：核延迟最高 1.64 倍（Synthetic 8,192 因果掩码，0.76466 毫秒降到 0.46659 毫秒）；端到端延迟最多降 15.34%（OmniDreams 移动场景长跑 2,045 帧，155.92 秒降到 132.00 秒）。 - 核心优化已合入 FlashInfer 主分支。

一、为什么 RTX Blackwell 需要另一套注意力管线

数据中心的工作负载以 softmax 为界，RTX Blackwell 的 BF16 注意力以 MMA 为界。NVFP4 的 TFLOP/s 更高，但 softmax、数据搬运与中间存储之间的依赖会让 Tensor Core 空闲。SageAttention3 用两级缩放解决 P 的动态范围问题：先归一化、再量化。

二、串行 CTA 与寄存器约束

每个 N128 tile，消费者 warp 依次执行 QK、softmax 与概率量化、PV；TMA 加载绑定 128×128，OMMA 限制在 m16、n8、k64，k=128 要发两条 k=64 的 MMA 指令且执行同步。生产者与消费者合计 62,464 个寄存器，占 SM 寄存器容量的约 95.3%，没有空间再放一块分数 tile。

三、寄存器回收：N128 拆成两个 N64

一半指数化并量化后，它的分数寄存器被回收、算下一个 tile 对应一半的 QK；相邻 tile 的工作交错起来，不用分配第二块完整的分数 tile，同时保留 4 个生产者 warp 与 8 个消费者 warp。在线 softmax 状态仍跨整个 N128 更新。

四、实测：核延迟与端到端延迟

核延迟表：8 个 case，加速比 1.17–1.64 倍，最高是 Synthetic 8,192 因果掩码。端到端表：13 行，LongLive 降 6.70%/6.54%，Helios 降 1.11–1.78%，OmniDreams 降 14.77–15.34%，Cosmos 3 Nano Policy Droid 降 1.70%。测量方法：每种实现 3 个全新进程，交替运行顺序，主动预热，重复的 CUDA 事件计时块；长跑行是完整预热生成的中位数。

局限

  • 只针对 RTX Blackwell SM120；OMMA 限制在 m16、n8、k64 是硬件约束。
  • Helios 上端到端收益只有 1.11–1.78%，不是所有模型都受益。
  • OmniDreams 每臂/场景只有 1 个进程，长跑行的统计力度弱于 LongLive 与 Helios 的 3 次中位数。

可复用的点

  • “死掉的寄存器立刻复用”：一半量化完就回收它的分数寄存器、算下一个 tile 的 QK，不用第二块完整缓冲。
  • 两级缩放：softmax 输出 [0, 1] 窄范围先归一化、再量化，充分利用 NVFP4 动态范围。
  • 测量方法：3 个全新进程、交替运行顺序、主动预热、CUDA 事件计时块；端到端按完整模型路径测，写明哪些注意力操作用 NVFP4。
