Sleep：窗口填满就睡一觉，循环前向细化 KV 缓存，上下文效率提升 2.39 倍（4⭐，No.140）

  • 原文：Sample-Efficient In-Context Adaptation via Sleep，arXiv 2611.32802，CMU / Yale / Microsoft Research，2026-11-24
  • 原文链接：https://arxiv.org/abs/2611.32802
  • 收藏日期：2026-11-27
  • 星级：4⭐
  • 主题：训练、并行策略（训练）、KV 缓存

一句话要点

在 1.2B 参数模型上，每攒满 256 个 token 就睡一觉、用 N−1 次循环前向细化 KV 缓存：N=4 时，达到无睡眠基线同样的预测 loss，上下文 token 用量减少 2.39 倍；参数量增加不到 2%，KV 缓存不增大；端到端解码延迟一次睡眠迭代时增加不到 3%，128k 前缀、三次睡眠迭代时增加 8%。

为什么值得读

  • 它把“睡眠”做成可算的机制：窗口 W=256 攒满就睡，睡眠期双向注意力 + N−1 次循环前向细化 KV，不是比喻，是训练与推理里都可跑的流程。
  • 样本效率的数字很干净：N=2/N=4 在 held-out 代码上达到无睡眠基线相同 loss，上下文 token 分别少 2.10×/2.39×；代价是训练算力约 N 倍，预填充约慢 N 倍，账算得清楚。
  • 推理成本不随睡眠失控：睡眠期的额外算力不占用清醒期，端到端解码延迟 N=2 时 +<3%、N=4（128k 前缀、3 次睡眠迭代）+8%；首 token 时间约按 N 缩放。
  • 机制小而完整：AttnRes（块大小 4，1/16 隐藏维做路由）+ GRU 式门控更新 K/V，参数量增加 <2%、KV 缓存不增大，改动面小。

核心结论

  • 方法：W=256，每攒满 256 个 token 睡一觉；睡眠期双向注意力，N−1 次循环前向细化 KV；AttnRes（块大小 4，1/16 隐藏维做路由）+ GRU 式门控更新 K/V。
  • 样本效率：N=2/N=4 在 held-out 代码上达到无睡眠基线相同 loss，上下文 token 分别少 2.10×/2.39×。
  • 成本：参数量增加 <2%，KV 缓存不增大；训练算力约 N 倍，预填充约慢 N 倍；端到端解码延迟 N=2 时 +<3%、N=4（128k 前缀、3 次睡眠迭代）+8%；首 token 时间约按 N 缩放。
  • 规模：预训练至多 1.2B 参数、至多 100B token。
  • 评估：负对数似然、少样本学习、推理成本、循环基线与 KV 门控，四组评估分开给数字。

分节要点

  • 样本效率与睡眠：问题定义，睡眠期的直觉与 N=2/N=4 的效率数字。
  • 背景：注意力与计算深度；深度循环、睡眠与训练算力。
  • 方法：睡一觉，细化 KV 缓存：W=256、双向注意力、循环前向、AttnRes + GRU 门控。
  • 实验设置：预训练规模（至多 1.2B 参数、100B token）与评估设置。
  • 评估：负对数似然（2.10×/2.39×）；少样本学习；推理成本、循环基线与 KV 门控。
  • 结论：上下文效率提升 2.39 倍，代价是训练算力与预填充约 N 倍。
